называет часть обязательных полей, я (промт-слой плагина, собирающий предпросмотр по частям) хочу
получать полный список непереданных полей одним отказом, чтобы задать оператору один уточняющий
вопрос вместо цепочки вопросов по одному полю за раунд.

аргументов — команда уже существует, путь обнаружения не меняется, меняется только форма отказа.

Когда вызов пакета отказывает, а причина не очевидна из текста одной команды — протухший токен,
недействующая сессия, непривязанный проект-хозяин, версия пакета, разошедшаяся с ожиданием
вызывающего, — я (промт-слой плагина, обязанный объяснить оператору причину отказа) хочу получить
одну сводную диагностику окружения, чтобы не воспроизводить обход `--version` / `token status` /
`auth-status` / `config show` собственными средствами.

**Путь обнаружения:** новая подкоманда `ktalk doctor --json`, вызываемая явно как первый шаг
разбора причины отказа — не автоматический перехват ошибки другой команды.

## Описание

Предмет — два независимых дефекта полноты диагностики в CLI пакета `ktalk-cli`. Оба явлены не
человеку за терминалом, а промт-слою плагина `ktalk`, который читает вывод команд, чтобы объяснить
причину оператору.

`create-meeting-preview` (issue #12) отказывает по первому непереданному обязательному полю:
`build_meeting_body` (`src/ktalk_cli/meeting_body.py:143-146`) поднимает `MissingFieldError` на
первом `None` цикла `_REQUIRED`, не накапливая остальные. Сам отказ до сетевого вызова верен
(NFR-9) — претензия только к неполноте перечисления: чтобы узнать все непереданные поля,
вызывающий обязан повторять вызов столько раз, сколько полей не хватает.

`ktalk doctor` (issue #14) — команда, которой в дереве 2.1.0 нет вовсе (`grep -rniE "doctor"
src/ktalk_cli/*.py` не даёт совпадений). Она агрегирует пять уже существующих поверхностей —
версию пакета, файл session-токена, живость авторизации, адрес пространства и источник, из
которого он взят, и обнаружение `.ktalk.toml` — в один `--json`-ответ вместо ручного обхода
вызывающим четырёх отдельных команд.

Требование не проектирует состав JSON-структуры, имена полей и то, какая из существующих команд
физически вызывается изнутри `doctor` — это решение SA. Требование не меняет класс ошибки и код
возврата `create-meeting-preview` (условие самой заявки #12). Требование не переопределяет
честность разделения «принято»/«отвергнуто» для `auth-status` — это предмет параллельного
требования по issue #11 (`talk-api-auth-modes`, BA-1); здесь описано только то, как `doctor` эту
честность **показывает**, агрегируя уже определённый там факт, а не переопределяя его.

## Почему `doctor` агрегирует, а не заводит нового источника истины

Заявка #14 сама называет приоритет низким — это улучшение, не дефект. Каждый из пяти пунктов
состава уже имеет собственную команду, отвечающую на него: ошибка не в отсутствии данных, а в
стоимости их сбора вызывающим (четыре отдельных вызова вместо одного). Поэтому `doctor` не вводит
новой логики определения истины ни по одному из пяти пунктов — он читает то же, что уже читают
`--version`, `token status`, `auth-status`, `config show`, и раскладывает результат по одному
объекту статуса на предусловие. Расхождение между тем, что говорит `doctor`, и тем, что говорит
одноимённая отдельная команда по тому же вопросу, было бы новым дефектом, а не устранением
старого — поэтому AC ниже прямо требует совпадения значений, не только их присутствия.

## Почему пара capability — расширение `host-project-config-discovery`, а не девятая capability

ADR-021 закрепил границу пакета в восемь capability. Из пяти пунктов состава `doctor` только один
(наличие и место `.ktalk.toml`) — прямой предмет `host-project-config-discovery`; ещё один (живость
авторизации) принадлежит `talk-api-auth-modes` и не переопределяется здесь. Три оставшихся пункта
(версия пакета, файл токена, адрес пространства) сегодня не принадлежат ни одной из восьми
capability пакета. Настоящее требование пристёгивает контракт агрегирующей команды к
`host-project-config-discovery`, поскольку среди восьми она единственная, чей `Purpose` буквально
про discovery окружения проекта-хозяина, — но не вводит по этим трём пунктам отдельной нормы
`### Requirement:`: `doctor` их читает и показывает, не устанавливая новой истины. Постоянный ли
дом нужен этим трём пунктам среди восьми capability, или обоснованно оставить их без отдельной
нормы — решение SA, не этого документа; называю явно как отказ от угадывания, а не как
принятое решение.

## Функциональные требования

### FR-47 — `create-meeting-preview` называет все непереданные обязательные поля одним отказом

При отказе `create-meeting-preview` по причине непереданных обязательных полей ответ называет
каждое поле, чьё отсутствие само по себе привело бы к отказу, — не только первое встреченное.
Множество полей, участвующих в этой проверке, не сужается и не расширяется этим требованием: это
любое поле, отсутствие которого сегодня поднимает `MissingFieldError` в `build_meeting_body`, в том
числе условно обязательные `pinCode` и (при `allowAnonymous=true`)
`anonymousAccessExpirationDate`. Класс исключения и код возврата команды не меняются (условие
issue #12).

**AC:**
- Given вызов `create-meeting-preview` не передаёт два и более обязательных поля, When команда
  отказывает, Then текст отказа называет каждое из непереданных полей, а не только первое —
  автоматическая проверка (фикстура с двумя и более отсутствующими полями).
- Given вызов не передаёт ровно одно обязательное поле, When команда отказывает, Then текст отказа
  называет это поле — поведение для единственного отсутствующего поля не регрессирует.
- Given все обязательные поля переданы, а `timezone` — в непринятой форме, When команда отказывает,
  Then отказ остаётся форматным (`TimezoneFormatError`), не переходит в перечисление недостающих
  полей — полнота перечисления не смешивает два разных класса отказа.
- Given отказ по нескольким полям произошёл, When проверяется факт сетевого вызова, Then ни один
  сетевой запрос не был сделан — автоматическая проверка (NFR-9 не ослабляется).

### FR-48 — `ktalk doctor` — одна сводная диагностика окружения

Команда `ktalk doctor` существует, не производит сетевых запросов на запись и не мутирует реестр, и
отдаёт с `--json` пять пунктов: версию пакета и её сопоставление с ожиданием вызывающего, наличие и
права файла session-токена, живость авторизации с тем же честным разделением
«принято»/«отвергнуто», что определяет `talk-api-auth-modes` для `auth-status`, адрес пространства
и источник, из которого он взят, и результат обнаружения `.ktalk.toml` (найден с путём / не найден
/ повреждён с причиной — `host-project-config-discovery`). Значение каждого пункта совпадает с тем,
что отдаёт одноимённая существующая команда на том же окружении.

**AC:**
- Given окружение с рабочим токеном и найденным `.ktalk.toml`, When вызывается `ktalk doctor
  --json`, Then ответ содержит все пять пунктов состава, и значение каждого совпадает с ответом
  `--version` / `token status` / `auth-status` / `config show`, вызванных по отдельности —
  автоматическая проверка (сравнение полей).
- Given `.ktalk.toml` в проекте отсутствует, When вызывается `ktalk doctor`, Then пункт о конфиге
  сообщает отсутствие явно, не как ошибку — автоматическая проверка.
- Given `.ktalk.toml` присутствует, но не проходит разбор, When вызывается `ktalk doctor`, Then
  пункт о конфиге называет причину, не проглатывает её в общий отказ — автоматическая проверка.
- Given `doctor` вызван, When проверяется исходящий сетевой трафик, Then единственный сетевой
  вызов, если он был сделан, — тот же вызов, что и у отдельной `auth-status`, не два независимых
  сетевых обращения на один и тот же факт — код-ревью/автоматическая проверка.

## Нефункциональные требования

### NFR-23 — Провал предусловия `doctor` виден и в теле `--json`, и в коде возврата

Урок 2026-09-04 (`content/lessons-learned.md`): признак в теле ответа без эскалации в код возврата
неотличим потребителем, читающим только код, от отсутствия отказа. `doctor` называет канал для
каждого предусловия явно: `--json` несёт статус по каждому пункту состава, а код возврата процесса —
ненулевой тогда и только тогда, когда хотя бы один пункт **действительно** провален — не «не
проверен» и не «неприменимо» (отсутствие `.ktalk.toml` результатом провала не считается,
`host-project-config-discovery`).

**AC:**
- Given все пункты состава удовлетворены или неприменимы (например, `.ktalk.toml` отсутствует —
  нормальная ветка), When `doctor` завершается, Then код возврата — 0 — автоматическая проверка.
- Given хотя бы один пункт состава действительно провален (протухший токен, повреждённый
  `.ktalk.toml`, отсутствующий или нечитаемый файл токена), When `doctor` завершается, Then код
  возврата — ненулевой, и это верно даже если вызывающий не разбирает тело `--json` вовсе —
  автоматическая проверка (регрессия: код возврата не зависит от факта разбора JSON).
- Given `doctor` вызван без `--json`, When читается человекочитаемый вывод, Then провалившийся
  пункт назван по имени в тексте, не только числом провалов — автоматическая проверка.

## Инварианты и Safeguards

**Содержательные:**
- Отказ `create-meeting-preview` по нескольким недостающим полям называет каждое из них в одном
  ответе; после починки не остаётся пути, на котором вызывающий узнаёт о втором непереданном поле
  только повторным вызовом (FR-47).
- Класс исключения (`MissingFieldError`) и код возврата `create-meeting-preview` не меняются —
  условие самой заявки #12.
- Отказ `create-meeting-preview` по-прежнему происходит строго до сетевого вызова (NFR-9) —
  полнота перечисления не откладывает проверку до после сети.
- `doctor` не производит ни одного сетевого вызова на запись; агрегируемая живость авторизации
  читает существующий сетевой вызов `auth-status`, не добавляет второй (FR-48).
- Значение каждого агрегированного пункта `doctor` совпадает со значением одноимённой отдельной
  команды на том же окружении; расхождение — дефект `doctor`, не одноимённой команды (FR-48).
- Код возврата `doctor` ненулевой тогда и только тогда, когда хотя бы одно предусловие
  действительно не выполнено; отсутствие `.ktalk.toml` — нормальная ветка, не провал, и не красит
  код возврата (NFR-23).

**Sensitive content:** N/A — предмет требования — форма отказа и состав диагностики, не значения
секретов. `doctor` показывает маску токена и факт живости авторизации, не сам токен и не тело
сетевого ответа авторизации — существующая дисциплина маскирования (`redact_secrets`) не
затрагивается.

- Механизм честного разделения «принято»/«отвергнуто» для живости авторизации — предмет
