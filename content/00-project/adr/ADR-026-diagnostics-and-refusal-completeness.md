# ADR-026: Сводная диагностика окружения и полнота отказа предпросмотра

**Дата:** 2026-09-08

## Контекст

[«Полное перечисление недостающих полей и сводная диагностика
окружения»](../../30-requirements/cli-diagnostics-completeness.md) (FR-47, FR-48, NFR-23, issue
#12, issue #14) требует двух независимых починок полноты: `create-meeting-preview` называет только
первое непереданное поле (`build_meeting_body`, `meeting_body.py:143-146`), а команды `ktalk
doctor` в дереве нет вовсе — пять существующих поверхностей (`--version`, `token status`,
`auth-status`, `config show`, обнаружение `.ktalk.toml`) обходятся вызывающим вручную.

Замер по issue #13 (тихий прочерк длительности «идёт») не подтвердился в своей формулировке:
`--json` уже отдаёт сырой ответ контура без домысливания. Замер вскрыл другой факт — тихий дефолт
`rec.get("duration", 0)` (`formatters.py:172`, тот же в `format_recording`) подставляет 0 вместо
отсутствующего значения в markdown-выводе. Ни одно FR/NFR требование пакета этот факт не называет
— он найден проектированием, не заявкой; нормативного носителя у него нет.

## Решение

**1. `create-meeting-preview` называет все непереданные поля одним отказом (FR-47).**
`meeting_body.py::build_meeting_body` собирает список отсутствующих полей — весь `_REQUIRED`-набор
плюс условно обязательные `pinCode`/`anonymousAccessExpirationDate` — до первого `raise`, и поднимает
`MissingFieldError` один раз со всем списком, если список не пуст. Проверка формата `timezone`
(`TimezoneFormatError`) выполняется только когда список пуст — два класса отказа не смешиваются.
Класс исключения и код возврата не меняются (условие issue #12); `.field` (строка) становится
`.fields` (список) — единственный внешний потребитель атрибута отсутствует (проверено, тесты читают
`str(exc)`). Детали — companion-спека §1.

**2. `ktalk doctor` — отдельный модуль `cli_doctor.py`, не рост `cli.py` (FR-48, NFR-23).**
`cli.py` — 445 строк без нарушения C13 сегодня (порог — длина функции, не файла), но
`registry.py` уже показал, к чему ведёт рост без расщепления (грандфазер 562, ADR-018 Д5). Пятый
подряд агрегатор в этом файле — сигнал завести модуль сейчас, тем же приёмом, что `cli_sync.py`/
`cli_token.py`. `doctor` не вычисляет новых фактов — читает пять существующих источников тем же
кодом, что их дежурные команды (общая функция там, где это возможно: `token_file.status_payload`
переиспользуется `cli_token.py` и `cli_doctor.py`), и один раз выполняет тот же сетевой пробный
вызов, что `auth-status` (ADR-025: `{"alive": bool, "note": str|None}` — контракт цитируется, не
переопределяется). Код возврата ненулевой тогда и только тогда, когда хотя бы один пункт
действительно провален: `token_file` — `not usable` (файл отсутствует, нечитаем или пуст — то же
поле, что `token status`); `auth` — `not alive`; `host_config` — `status == "malformed"`; `version`
— `--expect-min-version` передан и не выполнен. `host_config == "absent"` и `version` без запроса
сравнения — не провал (NFR-23). Полная таблица полей, псевдокод и точки правки — companion-спека
§2.

**3. Различение «значения нет» и «0 секунд» в длительности (находка, не покрыта требованием).**
`formatters.py::_format_duration` принимает `int | None`; `None` печатается как `—`, `0` — как «0
мин» (текущая арифметика не меняется для целого числа). Вызывающие места перестают подставлять
дефолт при чтении (`rec.get("duration")`, `data.get("duration")` — без второго аргумента `0`):
подстановка дефолта переезжает из точки чтения в точку форматирования, где `None` перестаёт быть
неотличим от факта. `--json`/raw-вывод не трогается — там уже честно нет ключа, если контур его не
прислал (проверено замером). Семантика «встреча идёт» — гипотеза, не проверенная ни BA, ни этим SA
(нужна активная встреча в момент вызова для замера); в решение не входит, нормативного носителя нет
— эскалируется отдельно владельцу, не специфицируется здесь.

**4. Три факта `doctor` без своей capability остаются aggregation-only — девятая capability не
заводится.** Версия пакета, файл токена, адрес пространства не несут собственного поведенческого
контракта (деградации, приоритета источников, отказа) — только чтение и показ значения. У всех
восьми capability пакета есть такой контракт (см. `openspec/specs/*/spec.md`); три факта doctor —
плоские данные без него. Растягивать `host-project-config-discovery` эти три факта не могут (BA-2
уже решила это верно текстом требования: растяжение касается только показа результата discovery), а
заводить ради трёх плоских полей девятую capability — цена структуры без предмета: если один из них
обрастёт собственной деградацией или приоритетом источников (например, адрес пространства — вторым
источником помимо `KTALK_BASE_URL`), тогда у него появится контракт и, значит, основание для
собственной capability — не раньше. Правка ADR-021 (граница восьми) не входит в это решение.

**5. Диспозиция долга ADR-003.** Изменение статуса/шапки/тела ADR-003 в этой задаче не выполняется
— это прямое нарушение процедуры supersede роли SA («не менять frontmatter/статус/тело старого ADR
при появлении нового решения; смена статуса старого ADR — отдельная задача с явным sign-off»).
Отчёт SA-1 («это задача PM») по факту следовал этой же процедуре корректно, только не назвал её.
Companion-диаграмма ADR-003 (`ADR-003-dispatch-flow.mermaid`) не редактируется по той же причине и
по решению самого ADR-025 («сохраняет историческую точность… и не правится») — она описывает
двухветочную диспетчеризацию, верную на 2026-08-13, ложную операционно после ADR-025. Читатель
приходит к текущему устройству через цепочку ссылок: ADR-003 → ADR-025 («Related articles») →
`ADR-025-dispatch-flow.mermaid` — цепочка уже существует и не нуждается в третьем звене здесь,
поскольку это решение не меняет диспетчеризацию авторизации.

## Последствия

**Позитивные:** промт-слой плагина получает весь список недостающих полей и весь свод диагностики
одним вызовом каждый — цена уточняющего диалога с оператором падает с N раундов до одного. Тихий
0-дефолт длительности снят без изменения контракта `--json`.

**Негативные:** оператор, использующий только `KTALK_SESSION_TOKEN` без файла токена (`ktalk token
set` не выполнялся), получает от `doctor` ненулевой код возврата по пункту `token_file`, хотя
`auth`-пункт того же ответа честно показывает рабочую авторизацию — расхождение видимо в самом
ответе, не скрыто, но требует от читающего сопоставить два поля, не одно.
`cli_doctor.py` — шестой файл-агрегатор рядом с `cli_sync.py`/`cli_token.py`/`cli_meeting*.py`,
плотность модулей `ktalk_cli` растёт.

**Смягчения:** негативный эффект token_file/auth называется явно в companion-спеке (NFR mapping) и
в контракте QA-author — не остаётся необнаруженным различием. Плотность модулей — цена уже принятого
паттерна расщепления по гейту C13, не новая.

## Альтернативы

- **`MissingFieldError` остаётся строкой, `doctor` печатает список отдельным полем `missing:
  list[str]` без замены исключения.** Отклонено — не решает issue #12 буквально (`str(exc)`
  по-прежнему называл бы одно поле, второй список пришлось бы парсить отдельно от текста ошибки).
- **`doctor` — метод `_cmd_doctor` внутри `cli.py`.** Отклонено — рост шестого агрегатора в файле,
  уже прошедшем через пять расщеплений по этой же причине (замер 4 координатора).
- **Токен-файл считается провалом `doctor` только когда `auth`-пункт тоже провален (композитная
  логика).** Отклонено — двойной учёт одного факта двумя разными механизмами (независимый статус
  файла + связь с другим пунктом) сложнее буквального чтения NFR-23 AC («отсутствующий или
  нечитаемый файл токена» — прямо в списке провалов) и создаёт скрытую связь между пунктами, которую
  FR-48 явно запрещает («каждый пункт… не переопределяет истину другого»).
- **Девятая capability `package-diagnostics` для трёх бездомных фактов.** Отклонено сейчас — трём
  плоским полям без собственного контракта нечего специфицировать сверх того, что уже пишет
  companion-спека этого ADR; решение переоткрывается, если один из фактов обрастёт деградацией.
- **Печатать длительность как `0 мин` всегда, полагаясь на `--json` для точности.** Отклонено —
  markdown-вывод для человека/промт-слоя не обязан читать `--json` параллельно, чтобы не поверить
  ложному нулю.
