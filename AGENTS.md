## Каталог ролей

Промт роли — универсальный контракт **в плагине** `nauta`, читающий локальный контекст в рантайме.
Пути столбца «Промт» — внутри плагина, не в дереве проекта; per-project копий промтов не существует.

| Роль | Команда | Промт (в плагине) | Зона |
|---|---|---|---|
| researcher | `/nauta:research` | `agents/researcher-agent.md` | Контекст-сборка: домен, конкуренты, чужой код. Требований и ADR не пишет |
| ba | `/nauta:ba` | `agents/ba-agent.md` | JTBD, FR/NFR, бизнес-правила, критерии приёмки |
| sa | `/nauta:sa` | `agents/sa-agent.md` | Компоненты, ADR, модели данных, API-контракты |
| qa | `/nauta:qa --mode=author`, `--mode=runner` | `agents/qa-author-agent.md`, `agents/qa-runner-agent.md` | Тест-дизайн до Dev'а; прогон сьюты и классификация падений |
| dev | `/nauta:dev` | `agents/dev-agent.md` | Реализация по архитектуре SA через TDD |
| devops | `/nauta:devops` | `agents/devops-agent.md` | Runbook, деплой, мониторинг, откат. Опционален |
| tech-writer | `/nauta:tech-writer` | `agents/tech-writer-agent.md` | Подача под аудиторию. Содержание не меняет |
| devsecops | `/nauta:devsecops` | `agents/devsecops-agent.md` | Secrets, SAST, supply-chain. **Opt-in** |
| compliance | `/nauta:compliance` | `agents/compliance-agent.md` | Gap analysis против **переданного** стандарта. **Opt-in** |

Координацию ведёт главный контекст через `/nauta:pm`; файла-субагента `pm` нет — человеческий гейт
держит только интерактивная сессия. Две роли включаются явным решением, а не по догадке о теме:
devsecops — в Dev-фазе по триггерам secrets/SAST/supply-chain; compliance — только когда назван
конкретный стандарт, встроенных регламентов у неё нет.

## Контракт вызова субагента

Четыре пункта обязательны в каждом брифе:

1. **Цель** одной фразой.
2. **Входные файлы** — пути к контексту; субагент читает сам и «вокруг» не ищет. Один файл — один
   исполнитель на время параллельной работы: пересечение разрешается **при выдаче задачи**
   интерфейсным контрактом на границе, а не дисциплиной `git commit --only` после факта. Прецедент
   — запись журнала уроков от 2026-05-07 (W4c-A) в `nauta`, не гипотеза.
3. **Ожидаемый артефакт** — какой файл должен появиться или измениться.
4. **Критерии приёмки** — как проверить, что задача выполнена.

Три правила поверх этих четырёх:

- **Право остановиться.** Конфликт задания с принятым решением — не решать самому: остановить эту
  ветку, зафиксировать в отчёте дословными цитатами обеих сторон, доделать остальное.
- **Замер вместо переноса.** Чужие числа не переиспользуются: мерить самому, называть команду,
  привязывать замер к коммиту внутри самой команды.
- **Мутация вместо зелени.** Сломать реализацию и показать, что проверка упала. Тест, который не
  может упасть, выглядит ровно как тест, который проходит.

**Изоляция.** Параллельные пишущие субагенты в одном дереве дают гонку: либо непересекающиеся
списки файлов, объявленные в брифе, либо отдельный worktree на пишущего. Ревьюеры читают и работают
параллельно с кем угодно.

## Каталог pipelines

| Pipeline | Назначение | Команда |
|---|---|---|
| project-planning | Оркестратор эпика: Researcher → BA → SA → QA-author → Dev → QA-runner → приёмка | `/nauta:pipelines:project-planning <эпик>` |
| ba-acceptance | Гейт: сверка критериев приёмки с реализацией, вердикт | `/nauta:pipelines:ba-acceptance <требование>` |
| critical-path | Зависимости задач эпика: критический путь | `/nauta:pipelines:critical-path <эпик>` |

## Куда пишет роль

Правило трёх домов — в `CLAUDE.md`. Никогда не пишутся в `content/`: test-report, acceptance-лог,
счётчик раундов, статус стадии, план эпика, открытые вопросы, пункты бэклога.
