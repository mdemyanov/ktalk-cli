# ktalk-cli

CLI `ktalk` для доступа к записям Контур.Толк (KTalk) и операционного реестра на SQLite.
MCP-слой снят ADR-022 целиком — единственная поверхность пакета сегодня CLI.

## Стиль (безусловное правило)
Писать сухо и сжато — в ответах, коммитах, статьях `content/`, докстрингах. Вывод, потом
обоснование; без преамбул, повторов и похвалы. Нет факта — так и сказать. Правило
действует всегда и приоритетнее привычки к развёрнутости.

## Entry points и команды
- `ktalk = ktalk_cli.cli:main` — единственная точка входа (реестр + чтение/запись контура)
- `bash scripts/check.sh --fast` — гейты контура (тот же прогон, что на pre-commit)

## Architecture
Один пакет `ktalk_cli`, единая точка входа CLI.
- Планирование отдаёт только предпросмотр (`create-meeting-preview`), создание — отдельная
  подтверждаемая команда (ADR-005/ADR-016)
- Пути API живут в таблице `OPERATION_PROFILES` (`auth.py`), не хардкодом в методах
- `calendar_reader.py`: окно календаря режется клиентом (сервер лимитирует 7 днями, потолок
  сегмента 100, `skip` не работает)
- `cli.py`: `_REGISTRY_FREE_COMMANDS` — команды, не открывающие БД; `contour_diagnostics.py` —
  диагностика недокументированного контура (ADR-004)
- Контракты API, режимы авторизации и эмпирика поведения (спеке верить нельзя) — в
  `src/ktalk_cli/CLAUDE.md`, грузится при работе с файлами под `src/`

## Conventions
- Ошибки API → человекочитаемые сообщения на русском; форматирование имён и длительности —
  в `formatters.py`. Async everywhere (httpx).

## CLI / реестр (registry)
- **SQLite — операционный source of truth**; `registry.md` в vault — генерируемое read-only
  зеркало (`ktalk export`), не редактировать руками.
- Статусы: `new → done|skipped|partial`, `partial → done`. Экспирация: записи `new` строго
  старше N дней (по умолчанию 7) → `skipped` при `sync`.
- Конкурентность: WAL + `busy_timeout=5000`, транзакция на операцию — параллельные `mark-*`
  из фоновых агентов безопасны.
- `--json` у всех команд печатает валидный JSON в stdout; ошибки — в stderr с ненулевым
  кодом возврата (навык/агент парсят stdout).
- Путь к БД бинарный → gitignore в vault (`.registry.db`, `-wal`, `-shm`). `ktalk migrate
  <vault>` — разовый импорт из markdown-реестров.

## Документарный контур (плагин nauta)
Планы `docs/superpowers/` остаются как есть, ретроспективно не переносятся. Решение принято —
пиши ADR; «что должно работать» — требование. PM декомпозирует, но не пишет код.
- `00-project/` — roadmap и ADR; `10-domain/` — исследования; `30-requirements/` — требования
  и AC; `40-architecture/` — спеки и контракты; `60-implementation/` — где реализация
  разошлась со спекой и почему; `70-operations/` — рунбуки (ADR-023 §3).
- Каждая статья (кроме `_index.md`) обязана нести `properties: - name: Тип контента` в
  object-нотации и быть достижимой по ссылке из `_index.md` — иначе гейт даёт error (нет
  типа) или warning (сирота).
- ADR длиннее 150 строк не проходит: детализация — в companion-спеку
  `content/40-architecture/<stem>-spec.md`.

## Пара «требование → контракт» (openspec/, ADR-021)
Строка `**Capability:**` (правило трёх домов ниже) указывает на контракт поведения в
`#### Scenario:`. Гейт проверяет форму пути раньше его существования: ссылка на несуществующую
спеку красит дерево громче отсутствия ссылки — не пиши её, пока файла нет. `openspec/specs/`
не заводится пустым каркасом — материализуется файл-за-файлом вместе с первой спекой
(`.nauta-ids.yaml`, пространство `scenario`). Граница восьми capability и порядок спек —
[ADR-021](content/00-project/adr/ADR-021-requirement-capability-pairing.md).

## Гейты (pre-commit)
`core.hooksPath=.githooks` → `scripts/check.sh --fast`. Требует `uv` в PATH. Пороги — в
`.nauta-gates.yaml`, обоснование — `content/40-architecture/ADR-001-nauta-contour-spec.md`.
- `src/ktalk_cli/registry.py` заморожен грандфазером на 562 строках: рост даёт error.
  Снимается расщеплением класса `Registry`, не поднятием потолка.
- `scripts/` и `.githooks/` — payload плагина (`/nauta:sync-scripts`, sha256 в
  `.nauta-scripts-basis.yaml`); правка руками делает файл конфликтом и он перестаёт
  обновляться — нужна своя версия, путь в `skip:`.
- Обход разовый: `git commit --no-verify`. Отключить: `git config --unset core.hooksPath`.

## Gramax (плагин gramax)
`content/` — валидный Gramax-каталог, `.doc-root.yaml` принадлежит Gramax, конфигурацию гейтов
туда не класть (для неё есть `.nauta-gates.yaml`). Новое значение свойства сначала объявляется
в `.doc-root.yaml`, потом используется в статье; `filterProperties` правится синхронно с
`properties`. В `_index.md` не бывает `properties`. Диаграммы — скиллом `mermaid`: отдельный
`.mermaid`-файл рядом со статьёй, не inline.

## Требования к рассуждениям

1. **Действуй первым.** Нужна информация — читай, не спрашивай.
2. **Факты, не версии.** Приводи вывод инструмента, цитируй файл. Не проверил — не утверждай.
3. **Верифицируй перед выводом.** «Работает», «исправлено», «готово» без вывода команды — не результат.
4. **Лаконичность.** Проблема → решение → результат.

## Порядок работы

Ролевую работу ведут субагенты плагина `nauta`, координацию — главный контекст (`/nauta:pm`).
Канонический порядок: Researcher (опц.) → BA → SA → QA-author → Dev → QA-runner → приёмка BA →
DevOps (если есть деплой). Каталог ролей и контракт вызова субагента — в `AGENTS.md`.

## Правило трёх домов

- Переживёт закрытие эпика как ответ на «почему так» → `content/`.
- Машинно-проверяемый контракт поведения → `openspec/specs/<capability>/spec.md`.
- Живёт только внутри эпика (очередь, стадии, счётчики раундов, test-report) → стор задач,
  **никогда** не в `content/`.

Статья в `content/` и её capability-спека объявляют пару строкой `**Capability:**`.
Язык дельты («теперь стало», «раунд 3», «переделано после ревью») в постоянном документе запрещён.

## Красные линии (универсальные)

- НЕ публиковать секреты: `.env`, токены, API-ключи, credentials, приватные ключи. Содержимое
  каждого нового файла проверяется до `git add`; реальное значение вместо плейсхолдера — блокер.
- НЕ включать PII: реальные имена, контакты, персональные данные.
- НЕ менять `content/.doc-root.yaml` и схему properties без решения SA и ADR.
- НЕ создавать статьи в `content/` без обязательных properties.
- НЕ брать задачу `/nauta:dev` без предшествующего артефакта SA.
- НЕ передавать тесты в QA-runner до стабов QA-author.
- Тесты и линтеры (если в проекте есть) — зелёные перед коммитом.

## Объём

Пиши плотно: таблицы и списки вместо простыней, ведущее предложение несёт главное. Сумма строк
`CLAUDE.md` + `AGENTS.md` — предмет гейта объёма; порог живёт в `.nauta-gates.yaml`, и без этого
файла проверка молчит, а «Errors: 0» валидатора означает «не проверялось», не «нарушений нет».

## Самоулучшение

- `content/lessons-learned.md` — append-only журнал уроков команды.
- Артефакты этого класса периодически компактятся; рабочий образец процедуры — шапка самого журнала.
- Находки об инструментах и API — в auto-memory, не в `content/`.
